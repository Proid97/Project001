# 개발계획 세 차례 자체 검토

확인일: 2026-10-15. 대상: [15_개발계획.md](15_개발계획.md).

사용자 요청에 따라 같은 계획을 세 차례 순서대로 읽고 고쳤습니다. 첫 검토 결과를 반영한 뒤 두 번째, 그 결과를 반영한 뒤 세 번째를 진행했습니다. 검토한 계획과 구현·실기기 결과는 구분합니다. Ponytail의 기본 full 지침을 유지합니다.

## 1차: 직접 만들 일을 라이브러리로 줄이기

발견: 엔진 기능을 쓴다고 적었지만, 실제로 재사용할 기능과 새로 작성할 코드의 경계가 흐렸습니다. 직접 만드는 파편 풀·난수·에셋 패킹도 더 줄일 수 있었습니다.

변경:

- Phaser의 Tween·시퀀스·파티클 풀·오디오·시드 난수를 먼저 사용합니다. 규칙에는 난수 함수만 넘겨 엔진과 분리합니다.
- 런타임 의존성과 개발용 도구를 구분했습니다. TypeScript·Vite·Vitest·Playwright·Biome·단일 파일 플러그인의 역할과 도입 시점을 정했습니다.
- 같은 크기의 이미지는 스프라이트시트로 시작하고, 기존 Pillow·FFmpeg 작업을 재사용합니다. 처음부터 직접 아틀라스 패커를 만들지 않습니다.
- 패키지는 설치할 때 호환 범위와 라이선스를 확인하고 정확한 버전·잠금 파일을 남기도록 했습니다.

확인: Phaser 공식 문서의 Tween·파티클 풀과 상한·난수 상태 저장, 각 개발 도구의 공식 안내를 확인했습니다. 계획에 반영한 문서의 표현과 링크를 검사했습니다. 패키지 설치·실행·절감량 측정은 아직 하지 않았습니다.

남긴 선택: Phaser와 TypeScript 기반 웹 시제품. 엔진 재선정이나 런타임 라이브러리 추가를 정당화할 측정 근거는 아직 없습니다.

## 2차: 실제 동작의 경계와 최악의 경우 줄이기

발견: 무작위 섞기의 반복·실패 복구가 복잡했고, 최종 저장 시점이 연출 중 앱 종료를 충분히 설명하지 못했습니다. 파편·음원 제한이 여러 객체에 나뉘면 전체 예산을 넘길 여지도 있었습니다.

변경:

- 연결 가능 검사는 같은 색 이웃 둘이 있는 가운데 볼을 찾는 방식으로 줄였습니다. 현재 규칙에서는 복잡한 경로 탐색이 필요 없습니다.
- 한 번 섞어도 연결이 없으면 기존 같은 색 볼 3개를 이어 놓고 나머지를 섞습니다. 현재56칸·4색·막힌 칸 없음에서는 색과 볼 개수를 바꾸지 않고 연결을 보장할 수 있습니다.
- 논리 정산 직후, 연출 전에 최종 상태를 한 묶음으로 저장하도록 바꿨습니다. 앱 복귀·중복 입력·외부 JSON 검사도 명확히 했습니다.
- 입력 전달 경로·AudioContext를 중복으로 만들지 않도록 했습니다. 파편80개와 효과음8개는 화면 전체 합계입니다.
- DPR 중복 적용·큰 화면의 픽셀 수·120Hz·앱 복귀 시 긴 경과 시간을 검사 항목에 넣었습니다.

확인: 3×3·3색 전체19683판과 연결 없는7×8·4색 사례를 독립적인 경로 탐색과 대조했습니다. 보존형 재배치500개에서 ID·색·특수 볼 표시·총56개를 보존하고 유효한 연결이 생기는지 확인했습니다. 게임 통합·브라우저·iPad 성능 통과를 뜻하지 않습니다. 결과는 [검증/계획검토.json](검증/계획검토.json)에 남겼습니다.

남긴 선택: 논리 정산과 화면 연출의 분리, 새 볼 자동 소거 없음, 성공 우선 판정. 현재 범위에서 이 세 가지를 바꿀 근거는 없었습니다.

## 3차: 개발 흐름과 실제 전달 경로 확인

발견: 개발 도구의 이름은 정해졌지만 검사 순서·타입 검사·단일 HTML의 에셋 추적·3D 제작 환경의 준비 상태가 부족했습니다.

변경:

- Vite 자동 갱신, Biome, 별도TypeScript 검사, Vitest, Playwright의 역할과 명령을 정했습니다. 검사 도구는 게임 실행 파일에 넣지 않습니다.
- 웹 배포용 분리 빌드와 개인 검토용 단일 HTML 빌드를 구분했습니다. 같은 소스를 쓰고, 첫 공유 시험부터 실제 이미지·음원을 넣어 해독을 확인합니다.
- 단일 파일 플러그인이 public 파일까지 자동으로 넣어 주지는 않는다는 조건을 반영했습니다. 모든 실행 에셋을 import 경로로 연결하고 원래 폴더에서 떨어져 오프라인 검사를 하도록 했습니다.
- WebKit 자동 검사·실제iPad·청음을 구분했습니다. 성능 측정 중 렌더링·테스트 감시 작업이 함께 돌아 결과를 흐리지 않게 했습니다.
- 현재Node·패키지 공개 메타데이터·Pillow·FFmpeg를 확인했습니다. Blender는 실행 파일을 찾지 못했으므로 준비할 일에 넣었습니다.

확인: 세 차례의 계획 해시·문서 링크·수치·미검증 표시를 확인했습니다. npm 공개 메타데이터7종의 버전·지원 범위·라이선스도 확인했습니다. 설치·빌드·보안 검사 통과 결과는 아닙니다.

남긴 선택: 3D→2D 출력과 코드 변형, 런타임Phaser 중심, 볼 하나부터 시작하는 개발 순서. 세 번째 검토 뒤 추가 엔진·UI 프레임워크·실시간 물리를 도입할 근거는 찾지 못했습니다.

## 현재 완료 범위

개발계획을 세 차례 순서대로 검토·수정했습니다. 실제 게임 환경의 설치 완료나 성능 개선률을 보고하는 문서는 아닙니다. 게임 규칙과 기존 목업·음원은 바꾸지 않았습니다.
